# Project Review Checklist

Use this checklist after the AI creates `PROJECT-BRIEF.md`.

Do not start coding until the project brief is reviewed.

## Project Identity

- [ ] Project name is correct
- [ ] Project slug is correct
- [ ] Domain or subdomain is correct
- [ ] One-sentence description is clear
- [ ] Project type is clear

## Problem and Purpose

- [ ] Problem statement is accurate
- [ ] Target users are correct
- [ ] Main value is clear
- [ ] The project does not sound too broad
- [ ] The project does not include unrelated features

## Roles and Permissions

- [ ] All user roles are listed
- [ ] Each role has clear permissions
- [ ] Each role has clear restrictions
- [ ] Approval or review permissions are clear

## Workflow

- [ ] Core workflow is correct
- [ ] Status flow is correct if needed
- [ ] “Done” is clearly defined
- [ ] Rejected or returned records are handled
- [ ] Blocked items are handled if needed

## MVP Scope

- [ ] MVP features are realistic
- [ ] Future features are separated
- [ ] Excluded features are listed
- [ ] The first working version is clear
- [ ] The MVP is not overloaded

## Database Strategy

- [ ] MongoDB is used for authentication
- [ ] MongoDB stores user accounts
- [ ] MongoDB stores password hashes
- [ ] MongoDB stores flexible app records
- [ ] Supabase Auth is not used
- [ ] Supabase is used only for storage and selected relational support
- [ ] File metadata storage is clear

## Final Approval

Only continue when this is true:

```txt
The project brief accurately describes what we are building.
```

Approval:

```txt
Approved: Yes / No
Approved by:
Date:
Notes:
```
